## T01 환경 점검

맥 칩·메모리·OS·Python을 기록하고 가상환경에서 카메라 입력과 MediaPipe 모델 로드를 확인합니다. PyTorch의 MPS 또는 CPU 선택, 모델 로딩과 짧은 학습 실행까지 조사합니다. 완료 증거는 실제 버전 목록·장치 확인·실행 로그입니다. 실행 앱의 카메라 권한도 확인합니다.

## T02 공개 영상 준비

UTA-RLDD의 소량 영상부터 접근·재생·시간 정보를 확인합니다. 출처·조건·원본·참가자 ID를 목록으로 만듭니다. 개발·검증·시험 참가자를 먼저 분리하고 이벤트 정답 표기 방법을 확정합니다. 원본 영상을 커밋하지 않습니다.

## T03 연결 계약

`interfaces.md`의 시간·유효 여부·이벤트 시작과 확정·세션 통계를 네 담당자가 검토합니다. 하나의 합성 예시를 모두 같은 의미로 읽는지 확인합니다. 계측·판정·저장·모델을 가상 입력으로 독립 개발할 수 있으면 완료입니다.

## T04 영상 측정

영상 파일과 웹캠 입력을 같은 측정 인터페이스로 처리합니다. 눈 기준값 보정, 고개 아래 방향 확인, 가림·옆얼굴의 측정 불가 처리와 재보정 조건을 구현합니다. 샘플별 측정값과 검출 실패 비율을 남깁니다.

## T05 상태·알람

가상 타임스탬프로 2초 눈 감김·3초 고개 숙임·1초 회복·0.5초 초과 입력 공백을 검증합니다. 프레임 속도가 달라도 같은 시간 판정을 내리고 같은 이벤트를 중복 저장·경보하지 않게 합니다. 실제 영상 측정 모듈과 연결해 확인합니다.

## T06 저장·집계

세션·이벤트·코칭 테이블을 만들고 시작·휴식·재개·종료를 기록합니다. 중복 이벤트 방지, 겹친 시간의 합집합, 관측 시간 0 처리, 재시작 후 조회·CSV 내보내기를 검증합니다. 10분 시간 오차 시험 절차도 마련합니다.

## T07 코칭 데이터

8개 상황의 사람이 검토한 초기 80~100건을 먼저 전달합니다. 통계 간 모순을 검사하고 800건 목표로 확장합니다. 같은 원형 시나리오·문장 변형이 서로 다른 분할에 섞이지 않게 하며 출처·검토자·그룹 ID·분할 목록을 남깁니다.

## T08 모델 학습

작은 자료로 학습 가능한 파라미터·손실·저장·재로딩을 먼저 확인합니다. 그 뒤 확정한 데이터로 학습하고 기본 모델과 튜닝 모델을 같은 생성 설정에서 비교합니다. 장치·메모리·시간·설정·데이터 버전·가중치 위치를 기록합니다. 가중치 원본은 GitHub에 넣지 않습니다.

## T09 화면

가상 이벤트로 보정·공부·휴식·기록 조회·코칭 상태 화면을 시작합니다. 미측정 비율·대체 응답 표시·세션 ID를 확인하고 화면 갱신이 카메라 중복 실행이나 작업 정지를 일으키지 않게 합니다. 이후 실제 저장·감지와 연결합니다.

## T10 통합

최신 프레임 처리와 모델 생성 작업을 분리하고 종료 시 통계 사본을 전달합니다. 코칭 중 다른 세션으로 이동해도 결과가 섞이지 않아야 합니다. 카메라 중단·재연결·모델 실패·중복 요청을 검증합니다.

## T11 영상 평가

보정과 독립된 시험에서 두 평가자가 정답 구간을 확정합니다. 최소 4명·유형별 30개 이벤트·정상/필기 60분을 목표로 F1·오경보·관측 가능 비율·FPS·알람 지연을 측정합니다. 공개 자료 평가와 책상 환경 재현 시험 결과를 별도 보고합니다.

## T12 모델 평가와 제출

시험 50건 이상에서 기본·튜닝·규칙 응답을 두 명이 이름을 가리고 평가합니다. 수치 충실성·유효 응답률·실패율을 보고합니다. 5회 전체 성공과 30분 연속 실행을 확인하고 실행 매뉴얼·보고서·3분 이내 백업 시연을 준비합니다. 확인하지 못한 목표는 미달·미측정으로 기록합니다.
