# 맥북에서 시작하는 구현 계획

설계 기준일은 2026-11-05이며, 당시에는 맥북에서 구현을 시작하기 전이었습니다. 아래 내용은 초기 설계·실험안입니다. 최신 구현과 남은 작업은 [README](../README.md)와 [전체 진행표 #13](https://github.com/Saewoong0106/student-drowsiness-coach/issues/13)을 기준으로 확인합니다. 제출일은 원 계획서의 2026-12-13을 임시 기준으로 삼고 수업 공지에 맞춰 갱신합니다.

## 구현 원칙

얼굴 영상 측정과 한국어 문장 생성을 분리합니다. **MediaPipe는 눈·얼굴의 점을 찾고, Python은 시간을 재고 수치를 계산하며, KoGPT2는 계산된 통계를 문장으로 설명합니다.** 공개 영상으로 시작하고 책상 환경에서 짧게 검증합니다.

## 난이도를 높이는 다섯 단계

### 1단계 영상을 열고 눈 위치 보기

OpenCV로 영상 파일을 재생하고 MediaPipe Face Landmarker로 눈 주변 점을 표시합니다. 같은 코드에서 입력만 웹캠으로 바꿀 수 있게 합니다. 얼굴 감지 성공 여부와 처리 속도를 기록합니다. 얼굴 위치를 찾는 것만으로 졸음 판단을 완료했다고 보지 않습니다.

MediaPipe는 이미지·영상·실시간 입력 모드를 지원하며 영상·실시간 입력은 프레임 타임스탬프를 받습니다. [공식 Python 안내](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/python)

완료 조건: 공개 영상 재생, 웹캠 입력 확인, 얼굴 가림·입력 종료 시 오류 대신 상태 표시.

### 2단계 눈과 고개의 수치 측정

EAR는 눈의 세로 벌어짐을 가로 폭과 비교한 값입니다. 눈을 감으면 대체로 작아집니다. 좌표를 실제 픽셀 비율에 맞춰 거리로 바꾸고 양쪽 눈을 함께 봅니다. 눈 주변 점이 존재한다는 이유만으로 가린 눈을 유효하다고 처리하지 않습니다. 추적 신뢰도와 가림·심한 고개 회전 시 실패 행동을 샘플로 확인합니다.

시작 보정에서 눈을 뜬 유효 프레임의 EAR 중앙값 B와 정면 고개 기준값을 저장합니다. 보정 데이터가 부족하면 다시 시도합니다. 고개 각도는 기준 자세 대비 변화로 사용하며 좌표 부호는 직접 숙여 확인합니다.

완료 조건: EAR·고개 기울기·유효 여부·시간을 한 행의 측정값으로 출력.

### 3단계 시간 조건과 기록 연결

계획서의 출발값을 구현하되 검증 후 고정합니다.

| 항목 | 진입 | 회복·처리 |
|---|---|---|
| 졸음 의심 | EAR < 0.65B가 2초 연속 | EAR ≥ 0.75B가 1초 연속이면 종료 |
| 고개 숙임 | 기준보다 아래로 20도 이상, 3초 연속 | 15도 미만으로 1초 유지 시 종료 |
| 미측정 | 얼굴·눈이 유효하지 않음 또는 입력 공백 > 0.5초 | 연속 조건 초기화, 끊긴 구간 표시 |
| 휴식 | 사용자 일시정지 | 감지 경보·공부 시간 중단 |

한 이벤트를 여러 번 세지 않습니다. 눈 감김과 고개 숙임은 별도 이벤트로 보관하고 대표 상태 시간은 중복 합산하지 않습니다. 초기 경보는 이벤트 확정 시 1회이며 재알림이 필요하면 최소 10초 간격으로 설정합니다.

실시간에는 단조 증가 시계를, 영상 파일 시험에는 영상 타임스탬프를 씁니다. 파일을 빨리 처리해도 영상 속 2초는 2초여야 합니다. 처리 시간은 별도 성능 지표입니다.

SQLite에 세션·이벤트·코칭 결과를 저장하고 `session_id`로 연결합니다. 활동 시간과 관측 가능 시간을 함께 보여 줍니다. 관측 가능 시간이 0이면 비율은 0%가 아니라 측정 불가입니다.

완료 조건: 깜박임 제외, 지속 눈 감김 경보, 필기는 자세로 기록, 가림·휴식·종료 처리, 재실행 후 기록 조회.

### 4단계 코칭 모델 학습

정상, 짧은 세션, 장시간 연속, 졸음 반복, 후반 증가, 고개 숙임 위주, 휴식 포함, 관측 부족의 8가지 상황을 준비합니다. 상황당 약 100건, 총 800건이 목표입니다. 원형 시나리오별 그룹을 먼저 나눠 학습 640·검증 80·시험 80건을 목표로 하며 그룹 분리를 수량보다 우선합니다. 같은 내용을 표현이나 숫자만 바꾼 예시는 같은 그룹에 둡니다. 최종 시험에는 사람이 독립 작성한 사례도 포함합니다.

입력에는 공부·휴식·관측 가능 시간, 졸음 의심 횟수·지속시간, 시간대별 관측량, 고개 숙임 횟수가 들어갑니다. 출력은 사실 요약·조심스러운 해석·다음 행동입니다. ‘60분 공부했으므로 집중도 90점’처럼 근거 없는 값을 만들지 않습니다.

KoGPT2는 125M 파라미터의 한국어 문장 생성 모델입니다. 지시를 따르는 최신 대화 모델과 같은 성능을 전제하지 않고 제한된 출력 형식으로 시작합니다. 모델은 CC-BY-NC-SA 4.0으로 배포됩니다. [공식 저장소](https://github.com/SKT-AI/KoGPT2)

초기 실험안: LoRA r=8, alpha=16, dropout=0.05, 학습률 0.0002, 최대 길이 512, 배치 2·누적 8, 3 epoch. 실제 학습 가능한 층을 확인합니다. GPT-2의 Conv1D 층을 대상으로 적용할 때는 `fan_in_fan_out=True` 설정을 확인합니다. `c_attn` 같은 실제 층 이름을 검사한 뒤 대상 층을 결정합니다. [PEFT LoRA 안내](https://huggingface.co/docs/peft/en/package_reference/lora)

입력·패딩 부분은 손실에서 제외하고 응답 부분으로 학습합니다. 토크나이저의 패딩·종료 토큰을 확인하며 정답이 잘린 예시는 수정합니다. 초기 80~100건 실험에서 손실 변화, 학습 가능한 파라미터, 저장 후 재로딩 결과를 확인한 다음 확장합니다.

완료 조건: 기본 모델과 튜닝 모델이 같은 입력으로 실제 응답 생성, 설정·분할·학습 로그 저장. 규칙 안내나 프롬프트만으로 미세 튜닝 완료를 대체하지 않습니다.

### 5단계 통합과 독립 평가

영상 처리와 모델 생성을 다른 작업으로 실행합니다. 화면은 감지 상태, 공부·휴식 시간, 측정 불가 비율, 세션 기록, 코칭을 표시합니다. 코칭은 종료된 세션의 통계 사본과 ID를 입력받고 생성 중·완료·실패를 구분합니다. 실패 시 규칙 안내를 보여 줄 수 있으나 모델 성공률에 포함하지 않습니다.

최종 시험 전에 데이터 목록·기준값·모델 버전을 고정합니다. 테스트 결과를 보고 임계값을 바꾸면 새 버전으로 분리하고 다시 독립 평가합니다.

## 맥북 환경 준비

맥 모델·칩·메모리와 macOS를 먼저 기록합니다. 개발 환경은 Python 가상환경으로 분리하고 호환되는 Python 3.11 또는 3.12 조합을 실제 설치 시험 후 확정합니다. 처음부터 버전을 임의로 고정하거나 전체 모델 학습을 시작하지 않습니다.

첫 준비의 설치 대상은 OpenCV·MediaPipe·NumPy입니다. 카메라·영상 확인 후 Streamlit, PyTorch·Transformers·PEFT를 추가합니다. 설치 성공만으로 호환 검증을 끝내지 말고 영상 읽기, 모델 로드, 짧은 학습·재로딩을 확인한 조합을 기록합니다.

- macOS 카메라 권한을 실행 앱에 허용하고 카메라 장치 선택을 확인합니다.
- Apple GPU 사용 가능 여부는 `torch.backends.mps.is_available()`로 확인합니다. MPS가 가능하면 소규모 학습을 시험하며, 불가능하면 CPU로 기능 확인 후 학교 GPU 등을 검토합니다. [PyTorch MPS 공식 안내](https://docs.pytorch.org/docs/stable/notes/mps.html)
- 실제 학습 시간·메모리는 장비와 샘플로 측정합니다. 맥북이라는 이유만으로 CUDA 코드를 쓰거나 특정 학습 시간을 보장하지 않습니다.
- 1주차에 학습 환경을 점검해 모델 작업이 마지막 주의 장애물이 되지 않게 합니다.
- Streamlit은 맥북 로컬 실행을 기준으로 합니다. 원격 서버의 OpenCV 카메라 번호가 사용자 맥북 카메라를 가리킨다고 가정하지 않습니다.

## 평가 목표와 계산 방법

원 계획서의 목표를 유지합니다. 아래 수치는 달성 결과가 아닙니다.

| 평가 | 목표 | 측정 방법 |
|---|---|---|
| 눈 감김·고개 숙임 | 유형별 이벤트 F1 ≥ 0.85 | 정답·예측 시간 IoU ≥ 0.5인 일대일 매칭, 중복은 FP |
| 오경보 | 정상 관측 기준 ≤ 2회/시간 | 정상·필기 구간에서 유형별 FP와 측정 시간을 함께 기록 |
| 처리 성능 | 평균 ≥ 10 FPS | 지정 맥북·입력 조건·실시간 추론 측정 |
| 경보 지연 | P95 ≤ 1초 | 눈 감은 순간이 아닌 2초 지속 조건 충족 시점부터 측정 |
| 시간 정확도 | 10분 시험 최대 오차 ≤ 2초 | 시작·휴식·재개·종료 3회 반복 |
| 기록 | 필수 이벤트 누락 0건 | 이벤트 원로그와 DB 대조 |
| 코칭 | 품질 ≥ 4/5, 수치 일치 ≥ 95% | 시험 최소 50건, 두 평가자 블라인드 평가 |
| 통합 | 5회 연속 성공, 30분 중단 없음 | 감지·경보·저장·조회·튜닝 모델 코칭 모두 완료 |

눈 감김과 고개 숙임이 겹치는 시간을 전체 시간에 두 번 더하지 않습니다. 미검출을 모두 제외해 성능이 좋아 보이게 하지 말고 전체 시험 결과와 관측 가능 비율을 함께 보고합니다. 짧은 정상 영상으로 측정한 시간당 오경보는 표본이 작다는 한계를 표시합니다.

코칭 평가는 근거 충실성·실행 가능성·한국어 가독성을 나눕니다. 기본·튜닝·규칙 출력을 같은 시험 입력에서 비교합니다. 관찰 수치와 제안한 휴식 시간은 구분해 평가하고, 빈 응답·숫자 미인용·대체 응답은 유효 응답률에서 별도로 셉니다.
