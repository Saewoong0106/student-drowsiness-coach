# 이슈·PR 댓글 양식

필요한 양식을 복사하고 내용을 채웁니다. `<...>`는 실제 값으로 바꿉니다. 모든 항목을 한 댓글에 넣을 필요는 없습니다. 작업의 최신 목적·담당·완료 조건은 이슈 본문에, 시간에 따른 진행·검증·리뷰는 댓글에 남깁니다.

## 작업을 시작할 때

```markdown
[시작] <이번에 진행할 작업>

- 담당: <이름 또는 GitHub 아이디>
- 브랜치: <feat/4-head-pose>
- 이번 목표: <완료할 동작 또는 결과물>
- 예정일: <YYYY-MM-DD>
- 선행 작업: <#이슈·PR 번호 또는 없음>
```

## 진행 상황이 바뀌었을 때

```markdown
[진행] <현재까지 확인한 결과>

- 완료: <코드·문서·실험과 확인 결과>
- 근거: <커밋·PR·로그·문서 링크>
- 다음 작업: <다음에 만들거나 확인할 것>
- 막힌 점·일정 영향: <내용 또는 없음>
```

## 도움이 필요할 때

```markdown
[도움 요청] <진행을 막는 문제>

- 환경·버전: <OS / Python / 커밋 또는 PR>
- 재현 방법·현상: <실행 순서와 실제 오류 문구>
- 이미 확인한 것: <시도와 결과>
- 필요한 도움: <누가 무엇을 확인하거나 결정해 주면 되는지>
- 일정 영향·다음 행동: <영향받는 작업과 기다리는 동안 할 일>
```

사람에게 알림을 보내야 할 때는 실제 GitHub 아이디를 확인한 뒤 멘션합니다. 단순히 오류가 났다고 쓰기보다 실행 명령과 오류 문구를 함께 남기면 다른 팀원이 바로 재현할 수 있습니다.

## 다른 컴퓨터에서 검증했을 때

```markdown
[검증] <Windows 또는 Mac에서 확인한 범위>

- 확인자·날짜: <이름 / YYYY-MM-DD>
- OS·CPU·Python: <실제 확인한 버전>
- 브랜치·커밋: <검사한 코드 버전>
- 검사 종류: <자동 검사 / 실제 카메라 / 소리 청취 / 문서 검토>

| 확인 항목 | 예상 결과 | 실제 결과 | 판정 |
|---|---|---|---|
| <예: 약 3초 눈 감김> | <횟수 1회·소리 1회> | <실제 확인 내용> | <통과/실패/미확인> |

- 실행 명령·로그: <재현할 명령 또는 결과 링크>
- 미확인 항목·다음 행동: <남은 확인 또는 없음>
```

카메라 없는 자동 검사가 통과해도 실제 카메라·소리 성공으로 표시하지 않습니다. 화면 확인, 소리 청취, 기록 조회는 각각 실제로 확인한 결과를 적습니다. 얼굴 영상·개인 세션 원본·비밀키는 첨부하지 않습니다.

## PR을 리뷰할 때

```markdown
[리뷰] <승인 / 수정 요청 / 의견>

- 확인한 범위: <코드·문서·실행 환경과 버전>
- 확인 결과: <좋아진 동작과 완료 조건 충족 여부>
- 병합 전 수정할 것: <파일·위치 / 문제 / 이유 / 기대 수정, 또는 없음>
- 후속 제안: <별도 이슈로 처리할 개선 또는 없음>
- 남은 확인: <다른 운영체제·실기기 등 또는 없음>
```

수정 요청은 상대의 작업 방식보다 확인 가능한 동작과 근거를 설명합니다. 병합을 막는 문제와 나중에 해도 되는 제안을 구분합니다. GitHub의 공식 승인·수정 요청도 필요하면 Files changed → Review changes에서 제출합니다.

## 작성 예시 읽기

다음은 형식 예시이며 실제 Windows 시험 결과가 아닙니다.

```markdown
[진행] 고개 각도 출력 연결

- 완료: 정면 기준에서 아래 방향 각도를 출력하도록 연결함.
- 근거: 해당 작업 커밋 링크를 여기에 기록.
- 다음 작업: 얼굴 없음·옆얼굴·필기 상황의 실제 결과 확인.
- 막힌 점·일정 영향: Windows 카메라 결과 미확인. Windows 사용 팀원 검증 필요.
```

이름·작업 순서·병합 규칙은 [팀 협업 규칙](../CONTRIBUTING.md)을 따릅니다.
